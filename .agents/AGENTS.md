# AGENTS.md

คำแนะนำสำหรับ AI coding agent (Claude Code, Codex ฯลฯ) ที่ทำงานกับ repo นี้

## ภาพรวม

โปรแกรมฝึกพิมพ์สัมผัสภาษาไทยบนแป้นเกษมณี มี 2 ตัวที่แยกกันโดยสิ้นเชิงแต่ใช้ข้อมูลชุดเดียวกัน:

- **เว็บ** (`web/`) — HTML/CSS/JS ล้วน ไม่มี build tool ไม่มี dependency เปิด `web/index.html` จาก `file://` ได้ทันที (ยกเว้นล็อกอิน ซึ่งต้องเปิดผ่าน http) เผยแพร่บน GitHub Pages ด้วย `.github/workflows/pages.yml`
- **เดสก์ท็อป** (`desktop/main.py`) — Python 3 + tkinter ไฟล์เดียว ใช้แค่ standard library

ไม่มี test suite, linter หรือ package manager

## คำสั่ง

```
python desktop/main.py            # รันเวอร์ชันเดสก์ท็อป
python tools/build_web_data.py    # สร้าง web/data.js ใหม่จาก data/words.json
python -m http.server 8000        # (ใน web/) ทดสอบล็อกอินที่ http://localhost:8000/
```

ตั้งค่า Supabase / Google / Gmail / GitHub Pages ดู `docs/setup-supabase.md`

## สถาปัตยกรรม

**แหล่งข้อมูลเดียว: `data/words.json`** มีสองคีย์
- `layout` — `{name, rows, bumps}` โดย `rows` คือผังแป้นเกษมณีทีละแถว แต่ละแถวมี array `base`/`shift`/`fingers` ที่ index ตรงกัน (รหัสนิ้วใน `fingers` คือ `LP LR LM LI RI RM RR RP` ส่วน `T` = นิ้วโป้ง ใช้ในโค้ดสำหรับ spacebar เท่านั้น) และ `bumps` = list ของ `[แถว, คอลัมน์]` ของปุ่มที่มีปุ่มนูน
- `lessons` — list ของบทเรียน `{id, title, keys, drills?, items}` เรียงตามลำดับการสอน `items` ต้องเป็นคำ/วลีจริงเท่านั้น ส่วนแบบฝึกที่ไม่ใช่คำจริง (เช่น `ฟฟฟ หหห`) ใส่ใน `drills` ซึ่งใช้เฉพาะตอนปิดสวิตช์ "คำจริง" `keys` คือปุ่มใหม่ที่บทนั้นแนะนำ (ปุ่มที่เรียนแล้ว = รวม `keys` ของบทแรกจนถึงบทปัจจุบัน) บทที่มี `"type": "paragraph"` จะสุ่มหยิบหนึ่ง item ทั้งก้อนแทนการต่อคำ

**`web/data.js` เป็นไฟล์ที่ generate** (`window.TH_DATA = ...`) เพื่อให้เว็บทำงานผ่าน `file://` ได้โดยไม่ต้อง fetch — ห้ามแก้มือ ทุกครั้งที่แก้ `words.json` ต้องรัน `tools/build_web_data.py` แล้ว commit ทั้งสองไฟล์

ฝั่งเดสก์ท็อปอ่าน `words.json` ตรงๆ ตอนเริ่มโปรแกรม

**ไฟล์ฝั่งเว็บ** (script ธรรมดา โหลดตามลำดับใน `index.html` สื่อสารกันผ่าน `window.TT`):
- `config.js` — URL และ anon key ของ Supabase ถ้าว่าง ระบบบัญชีปิดทั้งหมด
- `store.js` (`TT.store`) — localStorage, รอบที่พิมพ์จบ และการคำนวณที่ไม่ยุ่งกับ DOM: `weakKeys()` (ปุ่มอ่อน), `passed()` / `applyCriteria()` (ผ่านบทและเกณฑ์), `sumKeys()` (แผนที่ความร้อน)
- `app.js` (`TT.app`) — หน้าจอทั้งหมด: การพิมพ์ ผลหลังจบรอบ หน้าสถิติ หน้าตั้งเกณฑ์ การ์ดแนะนำ
- `account.js` — ล็อกอินและซิงก์กับ Supabase (`supabase/schema.sql`) โหลด supabase-js จาก CDN เองเมื่อมี config เท่านั้น เว็บต้องใช้งานได้ครบโดยไม่มีไฟล์นี้ ดู `docs/adr/0002-supabase-local-first.md`

**เว็บกับเดสก์ท็อปไม่ได้แชร์โค้ด** และฟีเจอร์ไม่เท่ากัน: เว็บมีโหมดบทเรียน/เวลา/จำนวนคำ/ปุ่มอ่อน, สถิติ, เกณฑ์ผ่านบท, บัญชี, สวิตช์ "คำจริง" (ปิดแล้ว `genWords()` ใน `web/app.js` จะสร้างพยางค์สุ่มปนคำจริงบางส่วน โดยใช้เฉพาะอักษรจาก `allowedChars()` = ปุ่มที่เรียนแล้วในโหมดบทเรียน หรือทุกปุ่มในโหมดอื่น; บท paragraph ไม่สนสวิตช์นี้) และธีมสว่าง/มืด ส่วนเดสก์ท็อปมีโหมดบทเรียน + ทดสอบ 30/60 วินาที และเป้าหมายเวลาฝึกรายวัน ค่าที่ซ้ำกันทั้งสองฝั่ง (ผังสีนิ้ว `FINGER_COLORS` ↔ `.f-XX` ใน `style.css`, ชื่อนิ้ว, ปุ่ม modifier รอบแถว `EXTRA`, regex/set ของอักษรที่ซ้อนบน-ล่าง `COMBINING`) ต้องแก้ให้ตรงกันเองทั้งสองที่

**การนับ** (นิยามอยู่ใน `GLOSSARY.md`):
- WPM = ตัวอักษรที่พิมพ์ถูก (นับทีละ code point รวมสระบน/ล่างและวรรณยุกต์) ÷ 5 ต่อนาที
- ความแม่นยำนับจาก keystroke — ตัวที่พิมพ์ผิดยังนับเป็น error แม้ลบทิ้งแล้ว
- "คำ" = ช่วงข้อความที่คั่นด้วยช่องว่าง

**การเก็บข้อมูล**: เว็บใช้ `localStorage` (คีย์อยู่ใน `TT.store.KEYS`: `thai-typing-settings`, `-theme`, `-history`, `-intro`, `-pending`) เดสก์ท็อปใช้ `~/.thai_typing_history.json`

`thai-typing-history` = `{v, rounds}` เก็บเฉพาะรอบที่พิมพ์จบ แต่ละรอบมี `{id, at, mode, lesson?, wpm, acc, sec, keys}` โดย `keys[ตัวอักษรเป้าหมาย] = [ครั้งที่กด, ครั้งที่ผิด, ครั้งที่จับเวลาได้, รวม ms]` ข้อมูลทั้งหมดของสถิติ แผนที่ความร้อน ปุ่มอ่อน และ ✓ ผ่านบท คำนวณจาก `rounds` นี้ เวลาซิงก์จึงแค่รวมรอบด้วย `id`

- รอบที่เริ่มใหม่กลางคัน (Esc, Tab + Enter) ไม่ถูกบันทึกเลย
- `settings.criteria` = `{all, shared, per, since}` ✓ ของบทนับเฉพาะรอบที่ `at > since[บท]` และ `since` ของบทจะถูกตั้งใหม่ตอนกดบันทึก เมื่อเกณฑ์ที่มีผลจริงกับบทนั้นเปลี่ยน
- ระดับของบท (`store.lessonLevel()`): `none` / `tried` / `pass` / `excellent` แสดงเป็นสีในแถบบทเรียน (ไม่มีคำบนจอ) **ผ่านดีเยี่ยม** คำนวณจากเกณฑ์ผ่านบทใน `store.excellentRule()` ผู้ใช้ตั้งเองไม่ได้ รอบที่ผ่านดีเยี่ยมในโหมดบทเรียนจะเลื่อนไปบทถัดไปให้ (`finish()` ใน `app.js`) และผลหลังจบรอบแสดงใน popup `#resultDlg`
- ซิงก์ทุกค่าใน `settings` ยกเว้นธีม ล็อกอินครั้งแรกบนเครื่อง = รวมรอบทั้งสองฝั่ง และใช้ settings บนคลาวด์ถ้ามี ออกจากระบบ = ล้างรอบและ settings ในเครื่อง (ส่งรอบที่ค้างใน `-pending` ให้เสร็จหรือเตือนก่อน)
